# Pegasus — notes for contributors and AI agents

Single-user OKX perpetual-swap manual trading terminal. pnpm monorepo, TypeScript ESM everywhere, Node 22.

## Layout
- `packages/shared` — domain types, zod schemas, web⇄api WS protocol, contract sizing (`sizing.ts`), signal and sizing-plan arithmetic and the `/api/signals` response types (`signals.ts`), the campaign rule (`campaign.ts`: pure functions of confirmed bars, the position and the pot) and the campaign API types (`campaign-api.ts`), decimal helpers. Both apps import from here; never duplicate these types.
- `packages/okx` — OKX v5 REST/WS client (signing, login, ping/pong, reconnect, resubscribe, order-book continuity by `seqId`/`prevSeqId`; OKX retired the book checksum and it is not verified). Pure exchange wire concerns; no domain logic.
- `packages/mock-okx` — local simulated OKX exchange used by `pnpm start --mock`, `pnpm dev:mock` and the API e2e tests (BTC and ETH swaps only). Isolated margin and the liquidation of tier-1 isolated positions on the mark price follow OKX's published rules (`src/engine/margin.ts`, sources in its header); cross positions are never liquidated.
- `packages/paper` — the paper exchange behind `pnpm start --paper`: the mock's matching engine (`@pegasus/mock-okx/engine`) with markets fed by OKX's live `books5` / `mark-price` / `tickers`, the account kept in `data/paper-account.json`, the time it was not running replayed from candles (`replay.ts`, rules in its header) and funding settled from OKX's funding history (`funding.ts`). It trades the campaign's ten USDT swaps by default (`PAPER_INSTRUMENTS`, plus `INSTRUMENTS`). In paper mode the API reads market data from OKX and sends everything signed, and its private socket, to this process (`PAPER_EXCHANGE_URL`).
- `packages/backtest` — backtester run from source (`pnpm backtest`): replays OKX history (daily and 12-hour candles, open interest) with Binance funding as the proxy and takes every decision from `buildSignalReport` in `packages/shared`, so a rule change is tested with the code the SIGNALS tab runs. The engine only keeps the book; its timing rules are in the header of `src/engine.ts`. Cache and output directories are git-ignored. This backtest is of the archived breakout framework. The campaign replay is `src/campaign/` (`pnpm backtest:campaign`; timing rules C1–C14 in the header of `src/campaign/engine.ts`; `--check reference/campaigns-okx.json` must reproduce the 497 reference campaigns; `--reconcile <ledger>` compares a pot's ledger with the replay). The API imports its pot replay through the `@pegasus/backtest/campaign` export.
- `apps/api` — Fastify server: `services/market-data.ts` (public/business sockets, stale-stream watchdog), `services/account.ts` (private socket + REST reconcile), `services/risk-engine.ts`, `services/order-service.ts` (orders, and moving / cancelling the stop algo orders the account service reads over REST), `services/signals.ts`, `services/kill-switch-sweeper.ts`, the campaign (paper only: `services/campaign.ts` runs the pot at every 12-hour close, with decisions from `campaign-step.ts`, orders through `campaign-orders.ts`, the ledger in `campaign-ledger.ts` and the replay beside it in `campaign-replay.ts`; C1–C13 mapped to their live counterparts in its header), exits beyond the stop (paper and loopback mock only, `EXITS_UNAVAILABLE` elsewhere: take-profit legs and the cost-price stop attached in `order-service.ts`, `exit-orders.ts` for the trailing exit placed after an order fills, `channel-trailing.ts` moving channel stops after each daily close, state in `exit-state.ts`; OKX semantics in `docs/okx-api-notes.md` 6.10), the trade journal (`journal.ts`, `journal-book.ts` with its assembly rules in the header, `journal-file.ts`; every trade from flat to flat, fed by `OrderService.onPlaced` and the account events, source from the client order id prefix: `pc` campaign, `ps` signal, `pg` manual), the per-coin campaign signals with their follow plans (`campaign-signals.ts`, `campaign-signals-plan.ts`), `ws/hub.ts` (fan-out to terminals), `routes/*`, `server.ts` (Host/Origin and token checks), `db/*` (Postgres store, or memory store that saves the kill switch and day baseline to `STATE_FILE`), `logger.ts` (console plus daily files in `LOG_DIR`).
- `apps/web` — React 19 + Vite terminal, including the CAMPAIGN tab (the pot's scoreboard, `components/CampaignPanel.tsx` and `components/campaign/`; the tab a page opens on while the campaign is enabled), the SIGNALS tab (the campaign rule coin by coin from `GET /api/campaign/signals`: `components/SignalsPanel.tsx` and `components/signals/`, the follow confirmation sheet `FollowSheet.tsx`), the exit editors (`components/exits/`, `components/positions/PositionExitsDialog.tsx`), the JOURNAL tab (`components/JournalPanel.tsx`, `components/journal/`) and the status banner. Zustand store with pure reducers in `src/store/reducers.ts`. Every text on the page comes from the dictionaries in `src/i18n/` (`en.ts` defines the entries, `zh.ts` must match it; components read them with `useT()`); the header's EN / 中文 switch picks one and keeps the choice in localStorage. Texts the store itself builds (banner alerts, sticky toasts) carry both languages (`Localized`).
- `scripts/start.mjs`, `scripts/launch-options.mjs`, `scripts/vite.stack.config.mjs`, `start.bat` — one-command launcher: builds the web app, starts the api and serves the built page on port 5174. `--campaign` runs a stack of its own beside it (page 5175, API 8788, paper exchange 9201, its page built into `apps/web/dist-campaign`, logs in `logs/campaign`), each page proxying to its own API.
- `docs/api.md` — the HTTP/WS contract between web and api. Update it when routes, error codes, settings or messages change. `docs/okx-api-notes.md` is the reference for OKX wire behaviour; `docs/strategy.md` is the trading framework: the campaign rule (`packages/shared/src/campaign.ts`), in its paper stage. `docs/archive/strategy-breakout.md` is the retired 55-day breakout framework that the SIGNALS tab and `pnpm backtest` still implement; code comments cite its section numbers, so it is kept as it is.

## Rules
- Money math only via decimal.js / `@pegasus/shared` helpers; values cross boundaries as decimal strings. Never `parseFloat` for arithmetic.
- OKX `sz` is in contracts. Convert through `sizeToContracts` / `notionalQuote`; respect `lotSz`, `minSz`, `tickSz`.
- Risk checks are enforced server-side in `RiskEngine.check`; the UI only previews.
- Only send `posSide` in long/short position mode; only send `reduceOnly` in net mode.
- Keep strict TS clean: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax` (use `import type`). Build optional fields conditionally instead of assigning `undefined`.
- Bars of 6H and longer are UTC-aligned: OKX's plain `6H`/`12H`/`1D`/`1W` bars open on UTC+8 boundaries, so they are mapped to its `…utc` bars at the wire boundary. Signals are computed on confirmed daily bars only, at the cuts listed in `SIGNAL_PHASES` (default both: 00:00 UTC from OKX `1Dutc` bars and 12:00 UTC built from `12Hutc` bars), each sized at 1/n of a unit.
- The API denies by default: `server.ts` decides authentication on the matched route (only `/api/health` and `/ws` are exempt from the bearer token) and refuses any request whose Host is not local or whose Origin is not listed in `WEB_ORIGINS`.

## Commands
- `pnpm typecheck` / `pnpm test` / `pnpm build` at the root run every package.
- `pnpm start` (or double-clicking `start.bat` on Windows) builds the web app and starts the whole stack from one snapshot; `--paper` (or `PAPER_TRADING=1` in `.env`) is paper trading: OKX live market data, a simulated account, no API key; `--campaign` (`start-campaign.bat`) is paper trading on the campaign pot's own account (`data/paper-campaign.json`, ledger `data/campaign-ledger.json`) with the campaign enabled; the API refuses `CAMPAIGN_ENABLED=1` outside paper trading; `--mock` runs it against the local mock exchange without touching `.env`, `--dev` uses the Vite dev server, `--no-open` does not open the browser.
- `pnpm --filter @pegasus/api test` runs unit tests plus the e2e suites against the in-process mock exchange (`test/e2e.test.ts`, `test/e2e-long-short.test.ts`, `test/e2e-read-only.test.ts`).
- `TEST_DATABASE_URL=postgres://... pnpm --filter @pegasus/api exec vitest run test/pg-store.test.ts` exercises the Postgres store (skipped without the variable).
- `pnpm backtest:campaign` replays the campaign rule (`--help` lists the flags; `--offline --cache <dir>` reads only a cache).
- `pnpm backtest` runs the archived breakout framework on BTC and ETH history (about two minutes; needs the network on the first run, then extends its cache); `pnpm backtest --help` lists the flags, `pnpm -s backtest --json` prints the summary object.
- `pnpm --filter @pegasus/paper test` covers the paper exchange with injected history; `apps/api/test/e2e-paper.test.ts` runs the API against it with the mock standing in for OKX's market data.
- `pnpm dev:mock`, `pnpm dev:paper`, `pnpm dev:api`, `pnpm dev:web` run one service each for debugging (README shows the variables that point a stand-alone api at the mock; all four `OKX_*_URL` overrides must be set together). The page must be opened at an origin listed in `WEB_ORIGINS` (default `http://localhost:5174` and `http://127.0.0.1:5174`).
