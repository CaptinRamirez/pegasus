# Claude 开仓顾问（Claude Entry Advisor）——开发策略提案（2026-10-17）

> 起因：持票人要把 Claude Opus 5.5 接进 Pegasus，让它帮忙制定开仓策略，并要求先弄清"最聪明的交易员在用哪些数据"。本稿是研究结论加开发策略。**状态：提案，未实施；董事会批准前不改任何规则和代码。**
>
> 研究方法：两路文献与实务检索（顶级交易员的数据清单；LLM 做交易决策的实证），加上用 curl 逐个核实 OKX、Binance、Deribit 等公开接口今天到底免费给什么、给多久。证据等级是检索结论的粗分（A 有多篇样本外研究，B 有单一研究或行业内严肃测试，C 只有访谈或流行说法），不是精确度量。

## 摘要

- 有样本外证据的数据只有三类：**趋势/动量**（A-）、**波动率状态**（B，用于仓位不用于方向）、**基差与资金费作为拥挤度**（A- 作为风险计量，C 作为入场信号）。这三类 Pegasus 已经有：20 日通道就是趋势，3 ATR 杠杆就是波动率状态，资金费否决在"看天气"影子里。
- 大家挂在嘴边的"天才交易员数据"——多空比、强平热图、持仓量阈值、链上净流入、MVRV、恐惧贪婪指数——在 1 天到 2 周周期上**没有一篇**可信的样本外研究支持，证据等级全是 C。
- LLM **直接预测方向**没有可信的样本外证据；2026 年的基准研究显示，同一模型同一数据跑多次，夏普从 -1 到 +2 乱跳，相邻两步决策会翻转。唯一活下来的用法是：**LLM 做结构化分析员和否决者，规则来做决定**；或者 LLM 写规则、回测来评判。
- 所以 Claude 在 Pegasus 的定位是：每根日线切点（现行 00:00 UTC；若 `cut-hour.md` 的 20:00 UTC 切点获批则随之）收盘后读一份固定格式的「案卷」，对规则给出的候选入场**排序、打分、给否决建议、用一句中文说清为什么**。它不预测价格，不下单，不改现行规则，只在屏幕上作为第三条影子线出现。
- Opus 5.5 的知识截止是 2026 年 6 月，2020–2026 上半年的回放对它是开卷考试，不能作为证据。干净的样本只有 **2026-07-01 起**：先回放这 3 个半月，再前向影子 90 天。
- 持仓类数据的免费历史有限：OKX 多空人数比和持仓量历史从 2024 年起，主动买卖量从 2020 年起，强平单只有最近几小时、必须从今天开始记录。每拖一天，前向样本就少一天。
- 预登记通过线：Claude 说"进"的战役要比它说"等/避"的战役结局明显更好（置换检验 p < 0.1），重问三次翻转率 < 10%，理由里每个数字都能在案卷里找到。任一条不过，顾问就只显示、不参与任何决策，和"看天气"一样。
- 诚实的预期：90 天影子大约只有 20 次规则入场，只能检出很大的效应。它最现实的价值是三件事：多个币同时触发时选哪个（池子每次押一半现金，选币很要紧）、避开明显拥挤的入场、把每次入场的理由写成持票人能读懂的话。它不会把一张 1/60000 的票变成月收入。
- 成本：每天一次调用约 0.1–0.3 美元，一个月 5–10 美元；后截止回放加三次重问一次性约 80–120 美元。池子本金 56 USDT，研究费比池子贵，要心里有数。
- 开发分四个工作包，每包结束时仓库都能编译、测试全绿；不碰 `campaign-step.ts`，不改 FollowSheet 的默认值。

## 1 研究一：最好的交易员在看什么

### 1.1 证据分级表

| 数据族 | 具体看什么 | 谁在用 | 证据 | 适用周期 | Pegasus 现状 |
|---|---|---|---|---|---|
| 趋势 / 时序动量 | 1–4 周收益、日线/周线趋势过滤 | 系统化基金、CTA、绝大多数波段交易员 | **A-**（Liu & Tsyvinski 2021 RFS：BTC/ETH/XRP 时序动量为正；Liu-Tsyvinski-Wu：市场、规模、动量三因子） | 1 天–4 周，顺势 | **已有**：20 日入场通道、10 日出场通道 |
| 基差 / 资金费（carry） | 年化基差、永续资金费水平与极值 | 基差套利台、量化基金 | **A-** 作为收益来源与拥挤度计量（BIS WP1087：高 carry 由加杠杆追涨驱动，预示崩盘风险）；**B-/C** 作为方向入场信号（BitMEX 的 8 小时均值回归测试是实务非学术） | 天–周 | **已有**：影子里的 72 小时资金费均值否决；回测用 Binance 资金费代理 |
| 波动率状态 | ATR%、已实现波动、波动率目标 | 系统化基金、风控台 | **B**（用于仓位和状态，不是方向） | 仓位 | **已有**：3 ATR 杠杆影子、ATR 红灯 |

| 期权 IV / 偏斜 / 看跌看涨比 | Deribit IV、25-delta 偏斜 | 期权台、波动率交易员 | **B** 预测波动率；**C** 预测方向 | 天–周 | 无 |
| 多空比、主动买卖比 | 多空人数比、大户持仓比、taker 买卖量比 | 散户、部分主观交易员 | **C**（广为流传，未见样本外研究） | — | 无（OKX 免费提供，见第 4 节） |
| 注意力 / 情绪 | Google 搜索量、恐惧贪婪指数、社交热度 | 散户、部分基金 | 搜索量 **B+**；恐惧贪婪 **C**（效应随状态变化，不稳定） | 1–几周 | 无 |
| 链上 | 交易所净流入、稳定币储备、巨鲸、MVRV、SOPR、ETF 流 | 分析师、长周期配置者 | **C**（未找到严肃的样本外研究；Griffin & Shams 的 Tether 发行研究有争议且不可交易） | 周–月 | 无；付费数据源不接 |
| 宏观与日历 | DXY、美国实际利率、FOMC/CPI、季度交割 | 宏观基金、事件交易员 | 事件日波动 **B**，方向 **C** | 事件日 | 无 |
| 新闻 / 上币 / 解锁 | 公告、解锁日程 | 事件驱动、山寨币交易员 | **C** | 小时–天 | 无 |

### 1.2 要点

- **证据最硬的三样东西，规则已经在用。** 这解释了为什么"看天气"影子加上资金费否决和 ATR 红灯后反而更差（6,640 对 21,430，见 `regime-snowball-v2.1.md` 首次回放结果）：波动率已经被 3 ATR 杠杆处理了一遍，再用它否决就是重复计数。
- **"天才交易员数据"的大部分是执行层信息，不是决策层信息。** 订单流、强平、盘口在秒到小时级别有用，到了日线收盘决策时信息已经消化完。把它们喂给一个每天只看一眼的顾问，是在喂噪音。
- **方向之外还有排序问题。** 池子每次新战役押一半现金，十个币一天内可能同时触发两三个入场。哪个先进、进哪个，现行规则按固定顺序排，这里是数据能帮上忙又不改规则的地方：相对 BTC 的强弱、资金费拥挤度、OI 变化作为**排序变量**，而不是**入场变量**，`regime-snowball-v2.1.md` 第 2.2 节已经提出过这个分法。
- **检索的局限：** 两路检索各做了六七次搜索，没有逐篇读全文，没找到点名具体阈值的顶级交易员访谈。等级是粗分。任何一项要进规则，先过回放，不以本表为据。

## 2 研究二：LLM 做交易决策的实证

### 2.1 最有信息量的研究

| 名称 | 年份 | 标的 / 周期 | 喂什么 | 结果 | 要命的漏洞 |
|---|---|---|---|---|---|
| Lopez-Lira & Tang《ChatGPT 能预测股价吗》 | 2023，v6 2025-10 | 美股日线 | 新闻标题分好/坏/中性 | 评分与次日收益相关，主要在小盘股和坏消息；随 LLM 普及收益衰减 | 股票不是加密；这是情绪分类，不是交易决策；边际在消失 |
| TradingAgents（多代理辩论） | 2024 | 三只美股，约 3 个月 | 价格、新闻、基本面、代理间辩论 | 论文称跑赢基准；博客引用夏普 5–8 | 3 个月窗口；成本滑点没算全；有社区质疑基准收益被错报（未核实） |
| Alpha Arena S1 / S1.5（nof1） | 2025 | 加密永续实盘约 2 周，每模型 1 万美元 | 价格与指标 | 一轮 Qwen 赢，一轮 Grok 赢，GPT 和 Gemini 亏 | 单次、两周、几个模型，各家报道数字互相矛盾：是噪音加营销 |
| LiveTradeBench | 2025 | 美股 + Polymarket，50 天实盘，21 个 LLM | 实时价格与新闻 | 排行榜高分与交易结果无关 | 窗口短 |
| Look-Ahead-Bench | 2026-01 | 5 只大盘股，2021 样本内对 2024 样本外 | 代理交易框架 | 普通 LLM 样本外 alpha 严重衰减；只有按时间点训练的模型站得住 | 概念验证 |
| AlphaForgeBench | 2026-02 | 策略设计基准 | 直接交易 vs LLM 写代码 | 直接交易：同模型同数据，夏普 -1 到 +2 乱跳，确定性解码也翻转；LLM 写代码再回测稳定得多 | 基准非实盘 |
| StockClaw（MAGNET 报告） | 2026 | 6 个代币含 BTC，4 小时方向 | 微调过的 8B 模型 | 平衡准确率 0.27，不如瞎猜（三分类基线 0.33）；作者承认价值在报告质量 | 行业报告、小模型 |
| MintEval | 2025 | LLM 把策略说明写成代码 | 策略规格 | 读懂了规格的实现里 79% 在 10% 以上的 K 线上与规格不符 | — |

### 2.2 结论

- **"LLM 预测方向"：没有可信的样本外证据，加密尤其没有。** 报出来的 alpha 多半来自训练数据记忆、短窗口、不算成本。后截止测试（只用模型知识截止之后的数据）是最低门槛。
- **"LLM 做结构化分析员 / 否决者"：是唯一站得住的架构。** 规则或回测过的逻辑做决定，LLM 解释、排序、只能拦不能放。AlphaForgeBench 的结论同向：让 LLM 写规则，把随机性关在生成环节，回测来评判——这正是本仓库已经在做的事（Claude Code 改 `campaign.ts`，`pnpm backtest:campaign --check` 评判）。
- **输出不稳定是结构性的。** 任何生产用法都要：固定 schema、同一案卷多问几次看翻转率、把"等"作为合法选项放在最前面。
- **数字幻觉要机器查。** Opus 5.5 比上一代更少报出输入里没有的数字（Anthropic 迁移指南的说法），但仍要用程序核对理由里的每个数字是否来自案卷。
- **成本不是问题。** 一次结构化的日线决策几千 token，缓存住系统提示后每天几美分到几十美分。
- **检索没找到的：** LLM 概率校准的研究、"总能找到理由交易"的量化证据、提示措辞敏感性。这三条按已知风险处理，在验证里补测。

## 3 结论：Claude 在 Pegasus 里做什么、不做什么

| 做 | 不做 |
|---|---|
| 每根日线在规则的切点确认后（现行 00:00 UTC，提案中的 20:00 UTC 见 `cut-hour.md`），读十个币的案卷，对处于 `entry` / `near` 状态的币给出：进 / 等 / 避、一个可校准的概率、今天候选里的排序、三条理由、什么情况下改变看法、一句中文 | 预测价格或方向 |
| 对 BTC 给一个"天气"判断（绿 / 黄 / 红）和一句理由，作为显示 | 下单、改仓位、改止损 |
| 在 SIGNALS 页每个币卡上作为第三条影子线显示（现有：3 ATR、看天气） | 进入 `campaign-step.ts`、改 FollowSheet 预填值 |
| 每个判断追加写进只增不改的日志，供打分 | 读新闻、社交媒体（不能回放、诱发"总能找到理由"） |
| 后截止回放 + 前向影子，对照预登记通过线 | 用 2026-06 之前的历史回放当证据 |

**为什么是 Opus 5.5：** 持票人指定；按 Anthropic 迁移指南，它在知识工作上比 Opus 5 更少捏造数字，`medium` 档就超过 Opus 5 的 `high`，价格 4/20 美元每百万 token。`effort` 从 `high` 起测，不要默认（默认是 `medium`）。

## 4 数据层：喂给 Claude 的「案卷」

案卷是每个币一段固定字段的 JSON，由 API 在收盘后拼装。原则：**只放能回放的、有明确定义的数值**；不放新闻、不放任何付费数据。

### 4.1 字段清单

**规则状态（已有，来自 `campaign-signals.ts` / `campaign.ts`）**
- 状态（entry / near / holding / add / exit / none）、最后确认日线收盘、入场线（20 日最高）、出场线（10 日最低）、收盘距入场线和出场线的百分比
- 该币最近 12 个月按规则的战役数、几次到过第一次加仓、几次爆仓、倍数中位（来自 `replayPot` 的战役记录）
- 若持仓：持仓天数、加仓次数、当前倍数、距出场线的百分比

**价格派生（已有或一行可算）**
- ATR%（20 日）、20 / 60 / 120 日收益、距 250 日最高的百分比、20 日已实现波动对 120 日的比值
- 相对 BTC 的 20 日强弱（该币 20 日收益减 BTC 20 日收益）
- BTC 单独一段：同上，加 BTC 收盘与 50 / 200 日均线的位置

**衍生品（OKX 公开接口，免费，已用 curl 核实）**

| 指标 | 接口 | 免费历史 | 用途 |
|---|---|---|---|
| 资金费 72 小时均值（8 小时归一）与近 90 日分位 | `/public/funding-rate-history`（已有） | 长 | 拥挤度 |
| 持仓量（美元）、7 日变化、OI/日成交 | `/rubik/stat/contracts/open-interest-history` 1D | **2024-01 起**（`end=` 分页） | 新钱进场还是空头回补 |
| 多空人数比及 30 日分位 | `/rubik/stat/contracts/long-short-account-ratio-contract` 1D | **2024-01 起** | 拥挤度（证据 C，仅作排序参考） |
| 主动买卖量比 1 日 / 7 日 | `/rubik/stat/taker-volume-contract` 1D | **2020-09 起** | 成交流方向 |
| BTC 期权持仓看跌看涨比、成交看跌看涨比 | `/rubik/stat/option/open-interest-volume-ratio` 1D | 约 72 天 | 对冲需求 |
| 杠杆借贷多空比 | `/rubik/stat/margin/loan-ratio` 1D | 约 180 天 | 拥挤度 |
| 24 小时强平笔数与名义（多 / 空） | `/public/liquidation-orders` | **只有最近约 7 小时 100 笔** | 必须从接入当天起每小时抓一次累计；此前没有 |

**可选第三方（免费、无密钥，已核实可达）**
- Deribit `get_historical_volatility`（BTC 已实现波动）、`get_book_summary_by_currency`（期权 mark IV）：做 IV 对已实现波动的比值
- alternative.me 恐惧贪婪指数：证据 C，只作显示，不进案卷的"决策字段"
- Binance `futures/data/*`：只有 30 天历史，不如 OKX，不接

**组合与池子（已有）**
- 池子自由现金、持仓数、本次收盘同时触发入场的币数、风控限额、杀开关状态

**不放的：** 新闻、社交热度、链上付费数据、任何无法在后截止窗口逐日重建的东西。

### 4.2 历史深度决定了验证能做多深

- 后截止窗口 2026-07-01 起：价格、资金费、OI、多空比、主动买卖量都能逐日重建；期权比值只覆盖后半段；强平没有。回放时缺的字段标 `null`，提示词里明说"此字段不可用"，不得用零代替。
- 前向影子：从接入当天起全字段。

### 5.2 Claude 调用

- SDK：`@anthropic-ai/sdk`，只加到 `apps/api`（回放 CLI 走 `@pegasus/backtest`，同样依赖）。密钥 `ANTHROPIC_API_KEY` 只在服务端读，和 OKX 密钥同样待遇，永不下发给页面。
- 模型 `claude-opus-5-5`；`thinking: { type: 'adaptive' }`；`output_config: { effort: 'high', format: zodOutputFormat(AdvisorVerdictSchema) }`，用 `client.messages.parse` 拿到类型安全的 JSON；`max_tokens` 8000；超时 120 秒；`fallbacks: 'default'` 加 beta 头 `server-side-fallback-2026-07-01`（Opus 5.5 的安全分类器拒答时换模型重跑，拒答仍要检查 `stop_reason`）。
- 系统提示固定不变并打 `cache_control`，案卷放在用户消息里。系统提示里写死：现行规则全文、池子参数、497 次战役的基础比率（88% 亏光本金、中位 5 天、到第一次加仓的比例）、"等"是合法且常见的答案、每个数字只能来自案卷、不得引用任何案卷外的事实或新闻。
- 一次调用覆盖十个币（横截面排序需要同时看见）；每次收盘一次。前向影子每天再**重问两次**同一案卷（共三次），记翻转率；这是验证成本的大头，通过线定了之后可以关掉。
- 失败处理：429 / 5xx 按 SDK 默认重试两次；仍失败写一条 `error` 记录并在横幅提示，不阻塞收盘流程（顾问失败不能影响池子）。

### 5.3 输出 schema（每个币）

```
verdict: 'go' | 'wait' | 'avoid'
pFirstAdd: number        // 若按规则此刻入场，先到第一次加仓（+5%）而不是先到出场/爆仓的概率，0–1
rank: number             // 今天候选中的名次
sizeMultiplier: number   // 建议注码倍数 0.5–1.0，只能减不能加，只显示
drivers: string[3]       // 每条必须引用案卷字段名和数值
invalidation: string     // 什么情况下改看法
oneLiner: string         // 屏幕上的一句中文
```
加一段 `market: { btcLight: 'green'|'amber'|'red', reason: string }`。`pFirstAdd` 的定义必须与打分脚本用的结局定义一字不差，否则校准无从谈起。

### 5.4 禁区

- `campaign-step.ts`、`campaign-orders.ts`、FollowSheet 的预填值、风控引擎：一行不改。
- 顾问的任何输出不得成为下单路径上的输入。要进决策，走 `regime-snowball-v2.1.md` 第 11.4 节同一程序：回放通过、董事会、30 天。
- 和 campaign 一样只在纸面模式启用（`ADVISOR_ENABLED=1` 在非纸面下拒绝启动）。

## 6 验证：预登记通过线

### 6.1 第一道门：后截止回放（接入后立即做，约 108 天）

- 用点时数据逐日重建 2026-07-01 到接入当天的案卷，每日一次调用，与前向影子同一提示、同一 schema。
- 对照对象：同一窗口里规则的每次入场（`replayPot` 的战役记录，以及实际纸面池子的账本）。
- 这是开卷之后的考试，但窗口里的行情 Claude 没见过。若在这一步就看不出分离，不必再等 90 天。

### 6.2 第二道门：前向影子 90 天

接入起算，每天一次正式调用加两次重问。

### 6.3 指标与通过线（写死，事后不改）

| 指标 | 怎么算 | 通过线 |
|---|---|---|
| 分离度 | 规则入场中，Claude 判 `go` 的战役与判 `wait`/`avoid` 的战役，比较"到第一次加仓"的比例和倍数中位；置换检验 | p < 0.1，且方向正确 |
| 排序 | 同一收盘多个候选时，`rank` 第一的币倍数中位 vs 其余 | 高于其余 |
| 校准 | `pFirstAdd` 对实际结局的 Brier 分数 vs 基础比率常数预测 | 不差于常数 |
| 一致性 | 同一案卷三次回答，`verdict` 翻转率 | < 10% |
| 可追溯 | 程序核对 `drivers` 里每个数字是否出现在案卷中（容差 1%） | 100% |
| 成本 | 日志 usage 汇总 | 月均 < 15 美元 |

### 6.4 诚实的样本量

规则一年约 76 次入场（497 次 / 6.5 年），90 天约 19 次，加后截止窗口约 20 次，合计约 40 次。这个样本只能检出很大的效应：比如 `go` 组到第一次加仓的比例 60% 对 `wait` 组 25%。小一点的差别检不出来，检不出来就是"不通过"，不是"再等等"。期权与强平字段在回放段缺失，影子段才有，不能拿来解释分离。

### 6.5 不通过怎么办

和"看天气"一样：顾问降为**只显示**，日志继续记，不再重问（省钱），半年后用更多样本再评一次。不改提示去凑结果；提示每改一版都是新的预登记，样本从零重数。

## 9 风险与局限

- **证据的天花板。** 第 1 节说明有效数据已在规则里；第 2 节说明 LLM 不预测方向。所以顾问能改善的是选币排序和避开拥挤入场，不是胜率的量级。对一张票的赔率（`strategy.md` 3.3）影响有限。
- **记忆污染。** 2026-06 之前的任何回放都不算证据，哪怕数字好看。
- **总能找到理由。** 把"等"放第一位、给基础比率、要求 `invalidation`，是已知的缓解，不是解决。前向影子里统计 `go` 的占比，若长期高于规则入场的历史到加仓比例，就是这个偏差在作用。
- **不稳定。** 翻转率是硬指标；若 Opus 5.5 在 `high` 档翻转率高于 10%，试 `xhigh` 一次，再不过就是不通过。
- **数据断档。** OKX rubik 接口无 SLA，字段可能改；取数失败时案卷标 `null`，判断照常，日志记缺失，打分时分组比较。
- **交易所单点。** 全部数据来自 OKX 一家，和池子同一单点，`new-method-panel.md` 已经说过。
- **持票人的时间。** 又一条影子线。若屏幕上三条影子让人看不懂，宁可只显示 Claude 一条，把 3 ATR 和看天气收进点开的层。
