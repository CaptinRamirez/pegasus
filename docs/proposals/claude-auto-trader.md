# Claude 自动交易员（纸面）——开发策略提案（2026-10-18）

> 起因：持票人把一段聊天截图给我看——把 BTC 的 15 分钟、1 小时、4 小时图喂给一个聊天模型，它给出"今天不做多，等反抽到 82,100–82,200 再空，止损 82,450，目标 81,700"这样的交易计划——然后说："我的意思是想让 Claude 自动化分析和下单。" 本稿替代 `claude-entry-advisor.md` 里"只显示、不下单"的定位：Claude 在美国时段自己分析、自己在**纸面账户**下单，代码管风险。**状态：2026-10-18 董事会全部批准（"全部批准"），WP1–WP3 当天建成：见文末「建成记录」。90 天样本（WP4）从持票人启动 `start-trader.bat` 那天起算。**

## 先说实话

- **截图那种分析，证据上站不住。** 均线排列、MACD 死叉、RSI、放量阴线，在前两天的文献检索里全是 C 级证据（`claude-entry-advisor.md` 第 1 节）；LLM 直接判断方向没有可信的样本外结果（第 2 节）；专家团队用你自己的数据测过 5 分钟顺势和 15 分钟方向，结论是"赚的等于手续费"（`new-method-panel.md`）。截图里那笔交易的算术：止损 0.37%、目标 0.55%，10 倍杠杆下一次往返手续费约等于本金的 1%，胜率要过 45% 才不亏手续费。
- **它有一条是对的，而且要写进代码而不是提示词：**"开仓之前先把止损价写下来，单子一进去就挂上止损。"
- **这件事值得做的理由只有一个：它是一张票，而且在纸面上。** 输了只输 API 费；赢了就是第一份"LLM 在这个账户上跑赢随机"的证据，没有人有这份证据。所以设计的重点不是让它赚，是让它**可被判死刑**：每个决定留痕、有随机对照、有预登记通过线。
- **它不是滚仓规则的替代。** 滚仓票（10 倍、20 日突破、加仓到尾部）继续在它自己的栈上跑；这个交易员在另一个纸面账户上，各算各的。

## 1 它做什么

| 做 | 不做 |
|---|---|
| 美国时段（默认 13:00–21:00 UTC，巴黎 15:00–23:00）内，在每根 1 小时收盘和被代码触发的 15 分钟事件上，读一份数字化的多周期案卷，决定：做多 / 做空 / 不做 / 平仓 / 移止损 | 看图片。截图里的东西全部用数字算出来喂它，便宜、可回放、可对照 |
| 输出固定格式：方向、入场方式（市价 / 挂单价）、止损价、目标价、信心、三条理由、什么情况下作废 | 自己决定仓位大小、杠杆、是否挂止损——这些是代码的 |
| 代码核对输出、过风控引擎、在**纸面交易所**下单并原子地挂上止损（现有 `order-service.ts` 的止损附挂） | 碰 OKX 账户。这一阶段没有交易密钥，`CAMPAIGN_ENABLED` 同样的纸面闭环 |
| 每个决定连同完整案卷、回答、token 用量、耗时写进只增不改的日志 | 改滚仓规则或它的池子 |

## 2 案卷：喂给它的数据（全部来自 OKX 公开接口，Pegasus 已在取）

**K 线与指标（代码算）**：15 分钟、1 小时、4 小时各最近 200 根；EMA 5 / 10 / 21 / 50 / 200；MACD(12, 26, 9) 与柱状图方向；RSI14；ATR14；当日 VWAP；成交量对 20 根均量的比值；每个周期"均线多头 / 空头 / 混乱"的判定由代码给出，不让模型自己数。

**位置与时间**：前一日高、低、收；亚洲与欧洲时段的区间高低；当日开盘至今的高低；距最近整数关口的距离；距美股开盘（13:30 UTC）和收盘（20:00 UTC）的分钟数；今天是否有 CPI / FOMC 这类日历事件（先手工维护一个日期表，不接新闻）。

**衍生品（日级）**：资金费 72 小时均值、持仓量 24 小时变化、多空人数比、主动买卖比、24 小时强平（`claude-entry-advisor.md` 第 4 节同一组接口）。

**账户与纪律**：当前仓位与浮盈、今日已交易笔数、今日盈亏、杀开关状态、上一笔的结局、距上一笔平仓的分钟数。

**不喂**：新闻、社交情绪、图片、别的模型的观点。

## 3 风险护栏（代码强制，模型改不了）

| 护栏 | 默认 |
|---|---|
| 标的 | BTC-USDT-SWAP 一个，和截图一致；跑通再谈第二个 |
| 时段 | 只在 13:00–21:00 UTC 开仓；21:00 UTC 仍有仓位则按模型最后一次给的止损持有到被打或次日（可选"收盘前强平"，由董事会定） |
| 同时持仓 | 1 笔 |
| 每笔风险 | 票面 2%（56 USDT 票是 1.1 USDT）；仓位 = 风险 / 止损距离，杠杆由此倒推，≤ 10 倍 |
| 止损 | 必须有，和开仓单一起提交；模型只能收紧，不能放远 |
| 每日 | 最多 3 笔；亏到票面 6% 当天停（复用 `RISK_DAILY_LOSS_LIMIT` 的杀开关） |
| 连亏 | 连亏 3 笔停 24 小时 |
| 加仓 | 不许逆势加仓；顺势加仓只在浮盈覆盖新止损时 |
| 输出校验 | 止损在入场的正确一侧、距离在 0.15%–1.5% 之间、目标比止损远；不合格的回答按"不做"处理并记日志 |
| 失败 | API 超时 / 拒答 / 限流：不做，记日志；已有仓位只靠挂着的止损 |

## 4 随机对照（判它死刑的尺子）

同一时刻、同一护栏、同一止损与目标距离（取模型给的）、同一仓位算法，**方向由掷硬币决定**，在第二个纸面账户上跑。它不是策略，是对照组：模型要赢的不是市场，是它自己的硬币版本。再加一个"从不交易"的基线（票面不变，只扣 API 费）。

## 5 预登记通过线（结果出来前写死）

- **样本**：90 天或 60 笔，取后到者。
- **必须同时满足**：扣手续费后净值 > 票面；净值变化好于随机对照（对照跑 20 次硬币序列的分布，模型落在前 10%）；最大回撤 < 票面 50%；每笔都有止损（100%）；同一案卷重问三次方向翻转率 < 10%；理由里的数字 100% 来自案卷。
- **任一不满足**：停掉下单，日志继续记，半年后再评；不改提示词去凑结果，提示词每改一版样本归零。
- **满本过线也不等于能上实盘**：实盘要另过董事会、要密钥、要真钱，这一稿不涉及。

## 6 架构（最小改动，全部在 apps/api，纸面模式才启动）

| 位置 | 做什么 |
|---|---|
| `packages/shared/src/trader.ts` | 案卷类型、决定的 zod schema、日志记录类型、指标纯函数（EMA、MACD、RSI、ATR、VWAP） |
| `apps/api/src/services/trader-dossier.ts` | 从 `market-data.ts` 取 15m / 1H / 4H K 线，算指标与位置，拼案卷；纯函数加取数器 |
| `apps/api/src/services/trader.ts` | 时钟（1 小时收盘 + 15 分钟事件触发，只在时段内）；调 Claude；护栏；经 `RiskEngine.check` 和 `OrderService` 下单并附挂止损；随机对照的第二路；`data/trader-log.jsonl` |
| `apps/api/src/routes/trader.ts` | `GET /api/trader`（状态、最后决定、今日记录）、`GET /api/trader/log`；`docs/api.md` |
| `apps/web` | 一个 TRADER 卡片：最后一次决定（方向、止损、目标、三条理由、作废条件）、下一次调用时刻、今日笔数与盈亏、护栏状态；交易本身进现有 JOURNAL 标签（client order id 前缀 `pt`） |
| `scripts/trader-score.mjs` | 第 5 节的六项，读日志和日志本 |

**Claude 调用**：`@anthropic-ai/sdk`，`claude-opus-5-5`，`thinking: { type: 'adaptive' }`，`output_config: { effort: 'high', format: zodOutputFormat(TraderDecisionSchema) }`，`client.messages.parse`，`max_tokens` 4000，超时 60 秒（15 分钟节奏等不起更久），`fallbacks: 'default'`。系统提示固定并缓存：护栏全文、"不做"是合法且常见的答案、每个数字只能来自案卷、不得引用案卷外的事实。密钥只在服务端，和 OKX 密钥同等对待。

**事件触发**（15 分钟级，代码判定，省钱也省噪音）：价格穿过前日高低 / 当日高低 / 整数关口；15 分钟均线排列翻转；有仓位时价格到达目标或接近止损。没有事件就只在整点调用。

## 建成记录（2026-10-18）

- **启动：** `.env` 里放 `ANTHROPIC_API_KEY=...`（只放这里），双击 `start-trader.bat`（或 `start-all.bat`，三套栈一起）。页面 5176，TRADER 标签页；纸面账户 `data/paper-trader.json` 从 56 USDT 开始，只有 BTC-USDT-SWAP。没有密钥时页面显示 blocked 并说明。
- **节奏：** 1 小时收盘加事件（`TRADER_CADENCE=hourly`）；时段 13:00–21:00 UTC；21:00 之后的仓位靠挂着的止损。
- **护栏（代码强制）：** 每笔风险 2%、每日 3 笔、日亏 6% 停、连亏 3 笔停 24 小时、止损距离 0.15%–1.5%、最多 10 倍、同时 1 笔、止损随开仓单一起提交（目标价作为止盈单一起提交）、限价单下一根 15 分钟收盘未成交即撤。
- **对照：** 掷硬币对照与交易员同一时刻、同一张数、同一止损和目标距离，按 15 分钟 K 线结算（同一根里止损和目标都碰到算止损），手续费 0.05% 双边，滑点 0.05%。
- **留痕：** `data/trader-log.jsonl` 每个决定连同完整案卷、回答、token 用量；`data/trader-state.json` 当日计数、持仓、对照、最近 50 笔结果。`GET /api/trader`、`GET /api/trader/log`。
- **成本显示：** 页面上按模型单价估算当日美元。
- **打分脚本（第 5 节六项）尚未写：** 90 天样本到之前再写，读日志即可。

## 修补（2026-10-18 晚，第一次调用前）

- 回答上限：董事会要求原来 4,000 的 100 倍；模型单次输出最多 128,000，取这个最大值（32 倍），改用流式请求；只按实际生成的 token 计费。超时 3 分钟，SDK 自动重试一次。
- 止损看守：每根 15 分钟收盘检查持仓在交易所上是否还有止损；没有就按记录的止损价补挂，价格已越过止损就市价平仓，并写进日志。
- 限价单部分成交：剩余部分立即撤掉，交易所随即为已成交部分生成止损。
- 不认识的仓位：交易员账户上有它没开的仓位（手动单、丢失的回执）时，状态显示 FOREIGN_POSITION，不调用模型、不开新仓，直到那个仓位平掉。
- 对照组：开新对照仓前，上一笔还开着的按现价结算入账，不再被覆盖。
