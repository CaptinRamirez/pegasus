# 日线切点 20:00 UTC（美国时段收盘）——回放实验（2026-10-18）

> 起因：持票人要在美国开盘时段做加密货币（2026-10-18）。现行规则的日线切点是 00:00 UTC（巴黎 02:00）和 12:00 UTC（巴黎 14:00），都不是持票人能在屏幕前的时间；美股现金收盘前后的 20:00 UTC（夏令时巴黎 22:00，冬令时 21:00）是。切点是规则的自由参数，497 次战役的证据是在 00:00 切的，所以先回放。**状态：已采用（2026-10-18）。董事会批准了回放，回放过了预登记线，随后批准采用（"可以"）。`CAMPAIGN_CUT_HOUR=20`：campaign 服务、SIGNALS 页、通道跟踪止损和池子旁的回放都按 20:00 UTC 的日线和 08:00 / 20:00 的 12 小时线运行，K 线从 OKX 4 小时线重建；纸面池子从零重开。**

## 时段本身没有方向性优势

OKX 1 小时 K 线，2024-10-14 到 2026-10-18，BTC 与 ETH：美国时段（13–21 UTC）占成交的 46%、小时方差的 50%，但两年累计 BTC x0.90、ETH x0.56（买入持有 x1.24 / x0.92），而且逐年翻转（2024 正，2025 BTC x0.78 / ETH x0.51，2026 正）。美国时段给的是流动性和大波动，不是方向。改切点赢的是可操作性，能不能改取决于规则在新切点上的结果不明显更差。

## 预登记（结果出来前写死）

- **怎么回放：** 日线和 12 小时线从 OKX 4 小时 K 线按切点重建（4 小时 K 线可回溯到 2020 年），`pnpm backtest:campaign --cut-hour 20`；切点 0 仍用交易所自己的 1Dutc / 12Hutc 线，`--check reference/campaigns-okx.json` 必须继续复现 497 次战役。
- **对照：** 第 3.2 节同一张表：75 个月初起点（2020-02 到 2026-04），每个起点一个 56 USDT 的池子，现行规则和 3 ATR 杠杆两个变体；加每个切点的单次战役目录（`--catalogue --exchange-limits`）。
- **切点：** 0（基线）、20（提案）、4、8、12、16（控制组，同一数据的其它切法，用来看切点之间的自然离散）。
- **指标：** 75 个起点合计取回（banked）；取回 ≥ 3,000 的起点数；池子存活天数中位；2022 年后起点里有取回的个数；目录的亏光比例、均值、最大倍数。
- **通过线：** 20 的合计取回和 ≥ 3,000 起点数**落在六个切点的离散范围之内，且不低于基线的 70%**，则采用 20（赢的是可操作性，证据不减）。低于 70% 不采用。高出其它切点一截先当运气：六个切点同时测，最好的那个一定看起来好。
- **已知噪音：** 同一根收盘多币同时入场时的顺序由收盘时间戳做随机种子（`sameCloseOrder`），切点一换顺序就换；这是切点效应的一部分，不另行剔除。
- **脚本：** `pnpm --filter @pegasus/backtest cut-hour-sweep --offline`，每个起点写到 `out/cut-hour-sweep.csv`。

### 对照预登记通过线

- **现行规则（10 倍）：通过。** 20 的合计取回 14,469 是基线的 119%，取回 ≥ 3,000 的起点 3 对 3，都在六个切点的范围内；存活中位 53 对 49 天，2022 年后有取回的起点 5 对 3。
- **3 ATR 变体：不过 70% 线。** 20 的 12,473 是其基线 21,430 的 58%，≥ 3,000 的起点 3 对 6；仍在六个切点的范围（2,634 到 100,951）之内。3 ATR 不是现行规则，这一行是给以后可能采用它的董事会看的：若采用 3 ATR，20:00 对它的回放更弱，但差别在下面说的噪音之内。

### 数字在说什么

- **切点之间的离散远大于 0 与 20 的差别。** 现行规则六个切点的合计取回从 3,970 到 85,952，差 22 倍；3 ATR 从 2,634 到 100,951。而同一套数据的单次战役目录在六个切点上几乎不动：452 到 483 个信号，亏光 81% 到 84%，均值 1.3 到 2.0。单次战役的赔率是稳定的；池子的结果是"运气的运气"——哪一根收盘恰好触发、同一收盘几个币谁先进（`sameCloseOrder` 以收盘时间戳为种子），决定了几万的差别。
- **所以第 3.2 节的表不是规则的期望值，是六次抽签中的一次。** 对一张票的赔率（3.3 节）应按六个切点合起来的离散去理解：取回 ≥ 3,000 的起点数在 0 到 3 之间（现行规则），不是"3"。这比切点本身重要。
- **切点 20 和 0 的差别在噪音里。** 按预登记，现行规则采用 20:00 是允许的：可操作性赢，证据不减，也不增。切点定了之后不再回头挑切点，六个里挑最好的那个（8）就是在挑运气。

## 采用后改了什么（2026-10-18）

- 设置 `CAMPAIGN_CUT_HOUR`（0 / 4 / 8 / 12 / 16 / 20，默认 0，`.env` 里设为 20）。切点不为 0 时，campaign 服务、`GET /api/campaign/signals`、通道跟踪止损和池子旁的回放都从 OKX 4 小时线重建日线和 12 小时线（`campaignBarsFromFourHours`），时钟按切点走；为 0 时一切如前，`--check` 仍复现 497 次战役。
- 账本记录池子启动时的切点；设置与账本的切点不一致时服务拒绝交易（`LEDGER_UNREADABLE`，提示把账本移走），不会悄悄错位。
- 页面上"00:00 UTC"的文案改为读切点（SIGNALS 的入场说明、退出编辑器的通道止损说明）。
- Claude 顾问（`claude-entry-advisor.md`）若建成，在同一切点调用。
- 纸面池子从零重开：旧的池子文件归档到 `data/backup-2026-10-18-pot2/`。
- **2026-10-28 的审核发现并修正**：服务里 `decideClose` 和 `walkMissedCloses` 判断「是不是日线收盘」时没有带切点，按 0 点算，所以 20 点切点下 10-18 起从未计划过入场（账本 21 步、0 次战役），停机补做时也找不到离场；正常运行时的离场不受影响。切点已传进这两处，`campaign-step.test.ts` 加了 20 点的用例（入场、离场、补做），`e2e-campaign-service.test.ts` 加了服务在 20 点切点的整套入场和停机补做。池子的纸面测试从修正后重启的那天起才算在跑。
